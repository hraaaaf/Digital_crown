## Scope / Goal / Success / Proof

Sign the executable with Windows Authenticode SHA-256 using `Set-AuthenticodeSignature`. Assert the OS `Get-AuthenticodeSignature` result is `Valid` and matches the exact external publisher thumbprint, stored **outside** the package. Sign the package's closed list of paths/sizes/SHA-256 with the *existing* B05-C1 Ed25519 admission (temporary pin also outside the package). Bundle into ZIP, extract into a different disposable ProgramData folder, require BOTH Windows Authenticode and the closed Ed25519 manifest to pass on that extracted candidate.

**Negative FUE in the same real runner**: mutate one signed byte and require both Authenticode and inventory rejection; replace executable with another genuine Authenticode signature from a second *locally trusted* lab certificate, require OS signature `Valid` but reject mismatched publisher thumbprint; replace with unsigned EXE and reject; inject extra file or remove helper and reject by closed manifest while signed EXE stays intact; restore bytes and re-admit original package. Remove all test artifacts and both CurrentUser test certificates and temporary trust roots.

## Exact boundaries / security review

The self-signed publisher and root trust are **generated by CI on the same runner**. This is an **Authenticode mechanics FUE, not publisher identity certification**. It must NEVER be used as a real production root, private signing key or cabinet certificate. No Authenticode timestamp, CA/enterprise chain validation, meaningful revocation, independent signer custody, TPM key, external antirollback ledger, two physical hosts or Windows Installer/MSI/MSIX packaging. The ZIP is a signed candidate *admitted by a separate test verifier*, not an actual installer and NOT the binary executed by an SCM service in this D1 workflow. Separate parent B05-C1 verified an Ed25519 candidate's actual SCM path. Python 3.12, cryptography, other pip packages and the helper runtime are still not bundled. The repository already has a guarded master-only Cabinet Certified Release workflow; do not compete with or trigger it. This PR only introduces a synthetic FUE and must not perform clinical, patient, network or release actions.
