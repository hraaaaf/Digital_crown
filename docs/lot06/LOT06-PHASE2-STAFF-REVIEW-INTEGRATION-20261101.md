# Digital Crown LOT06 — Phase 2 / clinical acquisition review integration, LAB gate

**Date**: 2026-11-01. **Parent**: [Phase 1 PR #1188](https://github.com/hraaaaf/Digital_crown/pull/1188), exact baseline `f2652b0f0dd01a9e1c838ff2c5c0aaac271df56a`. **Single canonical Notion page**: https://app.notion.com/p/3e677c66336281639beae2a946df1483.

## Decision: reuse existing product media stack, do not ship LAB transport

Production currently contains an authenticated patient media timeline and `ClinicalAsset` services: content-format detection/parsing, AES-GCM encryption, content-addressed tenant-limited storage, and readback. `imaging_acquisition_preflight_v15.py` is read-only by design; existing 03M/L test harness already validates real SQLCipher receipt/audit/outbox and signed device/ACK on an **isolated loopback HTTP** interface. These LAB endpoints cannot become a clinical transport without real native on-prem IPC and TPM provisioning. No actual 03M enrollment mechanism is a clinical authority.

## Phase2 integration slice: authenticated review ceremony plus real durable media

Added `isolated_fue_lot06c/phase2_staff_review_sqlcipher_lab.py` with **TEST-only mounted endpoints** on an explicitly constructed FastAPI fixture. They are **not mounted by backend.main** and are inaccessible in any cabinet or production environment. They use existing *real* FastAPI JWT and workstation/session guard, a real SQLCipher engine and staff/device/patient/WorkstationMode records.

Staff review flow under SQLCipher:
1. Existing synthetic device/capture proof from 03M is already provisioned by a separate test authority. GET review verifies staff account active/approved/licensed scope, workstation revision and revocation, patient preflight and two independent patient fields (patient dossier number and date of birth); binds capture, digest, device, tenant, station, byte size. Issues a fresh random, server-hashed review challenge bound to session, capture and a maximum two-minute deadline. Reissue invalidates earlier challenge.
2. GET preview is authenticated and returns *only* capture bytes that pass SHA-256/size binding; cache is explicitly disabled.
3. POST confirm requires an actual authenticated staff request, explicit confirmation boolean, exact selected patient ID, dossier, DOB, capture digest and one-time challenge. Wrong patient, wrong birth date, wrong dossier, wrong digest, replay, expired request, inactive staff or revoked workstation are denied before any clinical asset is committed. One SQLCipher write transaction commits the UI challenge consumption, staff approval to the existing 03M independent capture gate and two audit events.
4. Only **after** review approval, existing independent 03M verified device signature permits the signed media transfer through real HTTP/SQLCipher AES ClinicalAsset, durable receipt/audit/outbox. A lost ACK retry returns the **same** receipt with no duplicate asset. The endpoint still declares `clinical_receipt_authorized=false`; the review API is not a clinical signature.
5. No automatic patient match from filename, date, radiology worklist, or appointment. No trust in client-submitted patient or checksum alone; every parameter is rechecked against real server records. No persistent password, patient values or capture content in transport logs.

**Important accuracy:** the POST is generated by an automated test client. The tests prove backend identity binding and fail-closed ceremony; they **do not prove a real clinician saw the preview or clicked**. Frontend integration, human factors, 200% a11y, scanner/native Windows IPC adapter, power-cut with true filesystem durability and read-only receipt reconciliation under actual machine reset remain OPEN.

## Gates before any clinical activation

- Phase 1 Windows CI: true SCM/LocalService restricted service SID, authorized read/write vs CREATE_PIPE_INSTANCE deny, second user account/process denial — PASS in hosted Windows laboratory only.
- Phase2 FUE: staff review negative/positive, SQLCipher real media and duplicate ACK, session/expiry, cross-tenant/station revocation, scope/format/size; run prior 80 Linux/58 Windows regressions.
- OPEN: actual product route that uses Windows named pipe, not lab loopback HTTP; authorized installer/service ACL; actual UI and human UAT; TPM-bound device/ACK key lifecycle on cabinet PC; second physical Windows host remote denial; power-cut/restart/SQLCipher and ciphertext orphan lifecycle; independent review, owner GO.
- Scanner physical FUE remains LOT10.4. No claim of clinical equivalence from synthetic PNG.

**No activation:** `READY_TO_MERGE=false`, `PRODUCT_READY=false`, `CLINICAL_GO=false`. No merge, no Vercel, no migration, no clinic installation or live patients. Phase 2 is *in progress* until UX + native adapter and fault-injection evidence are complete.
