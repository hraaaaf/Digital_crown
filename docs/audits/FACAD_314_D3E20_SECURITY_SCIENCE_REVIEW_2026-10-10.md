## Perspective A — Hyper-V threat model / confidentiality (internal, design **6/10**; actual isolation proof **0/10**)
- **SEC-01 BLOCKER — official input and license.** No binary/dataset/hash/signature/download-chain proof, permitted nonclinical usage or offline activation pathway. Signed code alone does not establish benign behavior or legal authorization. Acceptance: approved vendor source, legal review, hashes tied to independent provenance, sample anonymization/nonclinical status verified; **do not acquire software in this lot**.
- **SEC-02 BLOCKER — live boundaries absent.** No actual hypervisor, guest device/policy/management inspection or negative controls. A VM without a NIC is **not air-gapped from its administrator**: PowerShell Direct uses `vmicvmsession` without virtual networking; `vmicguestinterface` supports host-guest file copy; Enhanced Session may redirect guest resources; KVP/heartbeat/time/shutdown/VSS and host console are separate host-management surfaces with distinct leakage/impact, not necessarily arbitrary-file-copy channels. Acceptance: independently reviewed host + guest inventory, two-sided enablement/state, least-privileged host account, device policies, negative controls, guest network and host-host isolation, pre/post VM state; prove actual operating system/image build and Hyper-V config.
- **SEC-03 BLOCKER — egress impossibility under current policy.** Proposed ingress is read-only ISO, but approved egress is **none**. A trace confined to guest can't be independently checked outside without an extraction or an in-guest independent observer; the latter still requires a controlled evidence protocol. Do **not** silently activate Copy-VMFile, PowerShell Direct, guest mounts, console clipboard, USB, virtual NIC or GitHub artifacts. Acceptance: separately approved *minimal verified evidence* pathway with scope, threat model, transfer direction, anti-identification, operator controls, retention/destruction and an actual independent reviewer. If impossible, reject Hyper-V route.
- **SEC-04 MAJOR — privileged host attack surface.** Hypervisor/host administrator, boot media author, compromised installer or management tools form the trusted computing base. A read-only virtual DVD prevents guest writes to media but does not establish runtime trust/immutability of host storage or safety of installer. Acceptance: dedicated disposable **non-clinical** host under explicit security owner, documented trust boundary, verified controls and incident procedure.
- **SEC-05 MAJOR — recoverable leftovers.** VM disks, checkpoint/snapshot diffs, pagefiles, crash dumps, ISO staging files, logs, backed-up data, hypervisor telemetry and host paths can remain after a guest teardown. Acceptance: inventory of every persistence site, prove teardown and host-side media disposal without patient data, independently reviewed retention procedure.
