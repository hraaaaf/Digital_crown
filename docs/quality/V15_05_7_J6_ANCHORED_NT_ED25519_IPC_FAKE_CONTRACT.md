Dix tests Windows de laboratoire tentent fichiers absents/corrompus, root/flag invalides, hardlinks, symlink cible, vraie junction NTFS, hook de substitution **réellement exécutée** du parent (renommage du dossier d'origine, création d'un nouveau dossier homonyme à contenu hostile ; test ROUGE si renommage Windows échoue) et cas témoin.

Douze tests Linux et Windows.

## Limites majeures non résolues / décision
L'ancre racine est acquise par un **chemin complet contrôlé par le test**, pas depuis un installateur Windows médical éprouvé ; aucune garantie de provenance ni d'ACL sur l'instance installée, aucun adversaire admin/SYSTEM, protections/oplocks File ID pendant activité concurrente, ni preuve d'intégration sur les chemins patients. La sémantique `OBJ_DONT_REPARSE` en mode user n'est pas un substitut universel à une revue des API Windows et du système de fichiers ; confirmer uniquement les cas observés sur le runner.
