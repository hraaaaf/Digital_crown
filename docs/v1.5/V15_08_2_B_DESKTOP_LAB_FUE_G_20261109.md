## ACTION / architecture

1. `backend/queue_core_desktop_lab.py`: fail-closed Desktop FastAPI mount at `/api/queue-core-lab`, only when `environment=test`, `DIGITALCROWN_QUEUE_CORE_LAB_ENABLE=1`, absolute preexisting directory whose basename starts `dc-queue-fue-`, exact synthetic marker, two existing distinct local SQLite auth/queue files. No auto-create, no clinical table migration, no ability to register an operator or privileged Admin from the HTTP service. Rejects non-test environments, missing files/marker, DB path collision and duplicate mounting. `backend/main.py` opt-in composition hook bypasses **only** the legacy clinical JWT/license middleware for that exact LAB mount; the B-2 live Bearer RBAC remains mandatory in the child app. Normal clinic env and route table remain unaffected.
2. `queue_core/security/operator_store.py`: test-only tenant-bound login helper resolves immutable bootstrap tenant server-side; browser never supplies tenant or role. `queue_core/service/http_transport.py`: opt-in LAB operator session POST and logout; response includes minimal effective role/grant **display hints** but no actor/tenant/queue membership. Server reauthorizes every actual command/SSE frame; client hints confer no rights.
3. `frontend/src/App.tsx`: lazy `/queue-core-lab` route behind existing ProtectedRoute, PermissionRoute(`agenda`) and `import.meta.env.DEV && VITE_QUEUE_CORE_LAB_PREVIEW === 'true'`. No change to the production WaitingRoomPage. `frontend/src/features/queue-core/QueueCoreLabPane.tsx`: token held in volatile state only, separate RECEPTION/STAFF controls, explicit denial messages and SSE reception. Invalid/revoked SSE session closes the visible queue immediately. UI uses semantic theme tokens and keyboard-accessible labels.
4. Separate **synthetic browser harness**, no clinic startup: `queue_core/tests/desktop_lab_fue_server.py` creates two temporary SQLite files, with fictitious tenant T1 / queues / visits / operators and marker. It binds one real FastAPI/Queue Core bridge to **127.0.0.1:18987** only with explicit `DIGITALCROWN_QUEUE_FUE_RUN=1` and a separate loopback Vite client on **127.0.0.1:5173**. `frontend/queue-core-fue.html` is a development-only standalone fixture (not actual clinical login); the main app integration route separately remains gated. `frontend/scripts/queue-core-desktop-fue-g.mjs` runs Chromium via Playwright-core, records real browser screenshots+network results and triggers an out-of-band synthetic Admin revocation using the marker file in the temporary root.
