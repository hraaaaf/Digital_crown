# P13-R — Remote Bare-Metal Execution Runbook

**Status:** PREPARED — execution requires AWS account/billing + offline primary signing key access. **0 P13 EP credited.**

## Goal
Run one exact Digital Crown release candidate on rented physical macOS + Windows-capable bare metal, including the real production-pinned authenticated update path, then preserve the final local Windows 11 + USB/NAS cabinet gate.

## Success
P13-R succeeds only when:
- all four package candidates come from the same Git commit;
- Windows 1.0.0/1.0.1 installers are Authenticode signed + timestamped by the existing Digital Crown private publisher;
- macOS 1.0.0/1.0.1 DMGs satisfy the existing private-distribution integrity contract;
- one unsigned dual-OS update payload is built from the exact 1.0.1 package bytes and HTTPS URLs;
- that payload is signed offline by the existing operational Ed25519 primary key whose public key is already pinned in the runtime;
- each installed frozen runtime verifies that same signed manifest without public-key injection, downloads and re-hashes its own target, creates a rescue backup and executes the certified platform apply/rollback path;
- real remote bare-metal Mac + x86 host execute the remaining physical gates;
- DR leaves the source machine and survives independent storage round-trips with identical SHA-256;
- both evidence documents and the P13 context manifest pass `validate-rehearsal`.

P13-R never closes or credits P13 by itself.

## 5. Build one exact dual-OS update payload
Upload only the **1.0.1 targets** to the private update prefix and create HTTPS presigned GET URLs long enough to cover the rehearsal window.

The URLs are bearer credentials. Do not commit or paste them into evidence.

On the networked operator machine, with the exact downloaded artifacts:

```text
python scripts/p10_build_update_manifest_payload.py \
  --sequence <next-production-sequence> \
  --version 1.0.1 \
  --windows-artifact DigitalCrownSetup-1.0.1.exe \
  --windows-url <private-https-presigned-url> \
  --macos-artifact DigitalCrown-1.0.1-arm64.dmg \
  --macos-url <private-https-presigned-url> \
  --expires-hours 24 \
  --output p13-update-payload.json
```

Use the next sequence from the update-signing/release ledger. Do not guess or reuse a sequence belonging to a different signed release.

The builder computes exact filename, byte size and SHA-256 for both targets. It refuses HTTP URLs.

## 6. Sign offline with the existing pinned primary key
Move only `p13-update-payload.json` to the offline signing machine using the established custody process.

Run:

```text
python scripts/p10_sign_update_manifest_offline.py \
  --private-key <offline-primary-private-key.pem> \
  --expected-key-id <primary-key-id-from-custody-record> \
  --payload p13-update-payload.json \
  --output p13-update-manifest.json
```

The signer:
- derives the Ed25519 public key from the private key;
- derives `keyid = sha256(raw_public_key)`;
- requires exact equality with `--expected-key-id`;
- requires that public key to equal one of the public roots embedded in the production runtime;
- signs the canonical JSON bytes used by `UpdateEngine.verify_manifest`;
- never prints or exports private key bytes.

Return only `p13-update-manifest.json` to the operator environment. Keep the private key offline.

Because the signed envelope contains presigned URLs, treat it as temporary sensitive operational material. Commit only non-secret hashes/key IDs/results after URLs expire or are revoked.

## 7. Installed-runtime authenticated update contract
PR #299 exposes the existing P10 engine through the **installed frozen backend**:

```text
POST /api/update/prepare
POST /api/update/{job_id}/apply
GET  /api/update/{job_id}/status
```

`POST /api/update/prepare`:
1. requires an authenticated admin;
2. passes the envelope to `UpdateEngine.verify_manifest` **without `public_key_b64` injection**;
3. therefore accepts only runtime-pinned active Ed25519 roots;
4. selects the exact current OS/architecture target;
5. downloads the authenticated HTTPS target;
6. checks exact size + SHA-256;
7. creates/stages a rescue backup;
8. returns a prepared job ID.

`POST /apply` then revalidates the platform package trust boundary before mutation:
- Windows: Digital Crown private Authenticode signer + local Root/TrustedPublisher trust + timestamp;
- macOS: the already-certified private macOS update integrity/trust contract.

The apply confirmation remains exactly:

```text
METTRE_A_JOUR
```

## 9. Windows P13-R sequence
1. Record EC2 host/instance type and Windows Server version.
2. Copy exact Windows 1.0.0/1.0.1 package pair + public `.cer` from the frozen workflow artifact.
3. Verify both installer SHA-256 values against `p10-clean-hosted-signed-pair.json`.
4. Import **only** `digitalcrown-private-codesign.cer` into LocalMachine `Root` + `TrustedPublisher`.
5. Verify both installers report valid Authenticode signatures + timestamp.
6. Install `DigitalCrownSetup-1.0.0.exe`.
7. Perform first launch, `/health`, normal relaunch and second-instance behavior.
8. Create deterministic synthetic cabinet fixture + media sentinel.
9. Create DR bundle + sidecar, verify local SHA-256, upload to independent S3 DR prefix.
10. Using the same offline-signed manifest, prepare a real update through `/api/update/prepare`.
11. Run the **controlled interrupted/failing update first** and prove automatic package/data rollback leaves version 1.0.0 healthy.
12. Prepare again with the **same signed manifest**; same-manifest retry is allowed by P10 trust state.
13. Apply successfully to 1.0.1.
14. Verify package self-test, installed target version, `/health` and synthetic cabinet continuity.
15. Download the macOS-created DR bundle for reverse cross-OS restore; verify exact SHA before restore.
16. Run Guided Restore through installed/frozen Digital Crown; verify DB marker + media sentinel + `/health`.
17. Exercise tampered bundle and wrong-secret rejection without real patient data.

Public trust bootstrap, Administrator:

```powershell
certutil -f -addstore Root .\digitalcrown-private-codesign.cer
certutil -f -addstore TrustedPublisher .\digitalcrown-private-codesign.cer
```
